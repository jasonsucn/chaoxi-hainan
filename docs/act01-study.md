## 1. 做法

### 1.1 构图：石头占主位，墙退后，沙压在脚边

- 左 1/4：竖排「玄武」+ 题记「最先露出来的不是沙，是火」+「火与海的接缝」；标题由 Canvas 绘制，
  所以会被水线切开（不是 DOM 文字盖一层遮罩）。
- 右中：一块主玄武岩柱（约 180×430 CSS px）+ 左侧矮柱 + 右侧残柱 + 脚边崩落石。
- 石后：一条低矮的珊瑚石灰墙，三段横缝、错缝、缺石、珊瑚/贝壳化石、墙顶草。
- 前景：黑沙坡、退潮沙纹、两处潮池、小卵石、成片的重矿物颗粒。
- 水线：`lineHigh = 0.435H`（满潮）→ `lineLow = 0.855H`（见底），潮位按钮固定在 `0.03 / 0.55 / 0.92`；
  高水线切标题和石顶，低水线把沙和潮池整片露出来。

### 1.2 程序化材质（无图片）

所有几何在 `makeLayout()` 里用固定种子（mulberry32）生成一次；同一套几何画两遍：

| 材质 | 生成方式 |
|---|---|
| 玄武岩 | 7 点柱顶断面 + 7 段轮廓（profile / lean / 崩角 / 突起台）+ 3 条节理横带 + 3 条柱面棱线 + 大断裂 + 气孔（64 个）+ 密集气孔（2 800 个 1px 点）+ 潮间带藤壶圈 + 顶面排线 |
| 珊瑚石灰墙 | 3 段（移动 4 段）错缝石块；每块独立 `fillA 0.030–0.040` / `lineA 0.28–0.42`；4–10 个气孔；4 处珊瑚/贝壳化石；3 块缺石；墙顶 2–3 丛草；石灰屑 |
| 黑沙 | 4% 沙面 wash + 3 000 个颗粒 + 6 片重矿物团 + 5 条沙纹 + 2 个潮池 + 卵石 |
| 纸/海 | 纸纹、盐光、焦散、光柱、海雪全部离屏生成一次；背景按水线缓存 |

关键手法：

1. **先画墙和沙，再把石头轮廓用 `destination-out` 挖掉，最后画石头。**
   线画只有 3–4% 填充，墙线会从石头里透出来；挖掉以后石头才真正“在前”。
2. **干湿同形。** `makeLayer('ink')` 与 `makeLayer('bone')` 使用同样的几何，
   只是调色不同；湿层不再开 `ctx.filter`（见性能一节），靠横向切片做折射。
3. **细线、点、排线都算线，不突破 3–4% 填充。**
   黑沙和玄武岩的“黑”由排线 + 点密度堆出来，不是实心色块。
4. **线重**：主轮廓 1.05–1.2px；0.8px 只给气孔环、化石、顶面排线（ART-DIRECTION 允许 0.6–0.8 的细线）。
   **填充**：石块 3.0–4.0%，沙/潮池/热 wash 4.0%；没有更大的实心填充。

### 1.3 干 / 湿

- 干：`inkLayer` 裁在水线上方，墨线 + 3.4% 填充。
- 湿：`boneLayer` 裁在水线下方，按 5px（移动 6px）一条横向切片重绘，
  每片水平位移 `sin(depth * 0.05 + t * 0.95) * min(6.5, depth * 0.022)`；
  另有 22px 的“湿膜”叠在水线上方，和一条 1px 骨白水线 + 泡沫点。
- 湿层整体用 `rgba(3,16,15,0.17)` `source-atop` 压一点海色，避免水下线条发白。
- 湿侧沙粒/气孔透明度乘 0.24–0.42；不压的话，满潮会变成一片白色“星空”。

### 1.4 热：从石缝里渗出来

- 按住石头：`heat → 1`，`tau = 1.9s`（约 3.6s 到 86%）；松手：`tau = 8.5s`（更慢）。
- 温度读数 `23 + 38 * heat`，四档：冷 / 温 / 热 / 烫；不显示进度条。
- 视觉：
  - 石肉 4% 珊瑚 wash；两层径向热晕（`lighter`）；
  - 14 条主裂纹 + 分支，阈值 `th` 不同，`reveal = smoothstep(heat, th, th+0.26)`，
    只在石肉 path 内（`clip(main.path)`）；裂纹是 1.1px 珊瑚线 + 3.9px 低透明光晕；
  - 石轮廓被烤暖（1.2px + 6px 光晕）；干侧 4 条上升热气；触点极慢的环；
  - 湿侧折射后同样绘制；水面下有珊瑚热倒影 + 7 条横向反光。
- 交互入口：覆盖在石头上的透明 `<button>`（`getRockRect()` 定位），
  `pointerdown` 加热、`pointerup/cancel` 停止；键盘聚焦后 `Space/Enter` 按住。
  潮位拖动/滚轮在其余区域，互不抢手势。
- 珊瑚朱 `#D8503A` 只在潮位尺 + 热出现；没有别的强调色。

### 1.5 海：一次生成的 Canvas2D，不是 WebGL

M0 的 `sea.js` 是逐像素 shader。在这台机器的软件光栅下实测 **6fps**（场景不动、只画海）。
研究改用：

1. `paperTex` / `detailTex`（焦散、光柱、海雪、大柔光带）/ `waterTex` 各生成一次；
2. `bg` 按当前 `lineY` **直切**成纸+海，缓存；只有水线移动 > 0.8px 才重建；
3. 每帧只 `drawImage(bg)`，再叠 240px 近水面天光、横移焦散带、14px 湿接缝、泡沫；
4. 直切与波形之间最多差 2px，由水线亮带遮住。

这样把每帧成本从“逐像素 fbm/caustic”降到“几张整图 + 一条渐变带”。

### 1.6 字与 UI

- 标题、题记、meta、竖排副题、材料标签全部画进 ink/bone 两层，所以都受水线切割。
- Noto Serif SC；标题 500、正文 400；英文标签 6.8–8.8px + 宽字距 Consolas/Sans。
- DOM：右上索引 `01 / 05`、三个潮位按钮、右侧珊瑚潮位尺、底部读数、石温、提示。
- 移动端：去掉 meta 和墙/沙标签，只留石头标签；题记缩到 8.6px，标题 91px；`01/05` 保留。

## 2. 可复用 / 可拆给 R1 的部件

1. **一张几何、两套调色。**
   `makeLayout` 只生成点、路径、碎裂、气孔；`paintWall / paintSand / paintRock / paintType` 接受 palette。
   R1 直接把 `study-scene.js` 的绘制部分搬进 `act.js`，保留 `draw(g, mode)` 的思路。
2. **`eraseUnderRock`。**
   墙和沙先画，再用 `destination-out` 沿主/侧柱轮廓挖掉，最后画石头。
   这是线画“前后遮挡”最便宜的做法，比给石头加实心填充更符合 3–4% 规则。
3. **`drawWetSlices(line, t)`。**
   5/6px 切片 + 正弦横移；R1 用 shell 的 `ctx.waveAt`/`clipBelow` 就能复用。
   注意湿侧透明度乘 0.24–0.42（沙粒/气孔），否则水下会过曝。
4. **热状态机 + 命中层。**
   `heat`、`tau`、`reveal`、`getRockRect()`、透明按钮；直接从 scene 模块搬到 act。
   键盘 `Space/Enter` 已在 lab 里验证。
5. **潮位映射。**
   `lineHigh / lineLow` + 三个 stop + `?p=` 别名；R1 可以直接把 `p` 映射到 `s.p`。
6. **海缓存 / 降级方案。**
   如果 R1 的共享 WebGL sea 在低端设备掉帧，可保留这个 2D 缓存海作为 fallback：
   `buildBackdrop(line)` 直切 + 湿接缝遮差，代码约 120 行。
7. **文案与标签。**
   「珊瑚石灰墙 / 玄武岩 / 黑沙」三条图版标签的锚点/字号；移动端只留一条的裁剪逻辑。

## 3. 性能记录

环境：本机 DSH 内置 360ChromeX（软件光栅，非真机 GPU）；1280×800；DPR 1。
同一浏览器同时开着几个 act lab 时会互相抢 CPU，读数波动很大。

| 方案 | 实测 |
|---|---|
| M0 风格 WebGL 逐像素海（先做的一版） | **6 fps**（只画海；场景被压到 6） |
| 只画场景、不画海 | **57 fps** |
| Canvas2D 缓存海 + 场景 | **60 fps**（空浏览器、最终参数） |
| 同一浏览器同时 6–8 个 lab | **23–41 fps**（环境抢占；不是单页成本） |

单次构建：

- `build 63.3 ms`（1280×800，含纸/海/焦散生成 + 两遍场景 + 2 800 气孔 + 3 000 沙粒）——一次性，切换潮位不重建。
- 每帧：1 张背景 cache + 55 条湿切片 + 22px 湿膜 + 场景热（只有按住时）+ 近水面 240px 渐变/焦散 + 泡沫；没有 `ctx.filter`、`shadowBlur`、逐像素 shader。
- 尺寸：两张 1280×800 场景层 + 纸/海/细节/背景各一张，约 8–10MB 位图；390×844 明显更小。

**最重要的性能教训**：不要在 bone 层的 `ctx` 上先设 `filter = 'blur(0.42px)'` 再画几千个沙粒/气孔。
每次 `fillRect` 都会触发一次模糊处理，首帧会卡到 30s+（真的发生过）。
湿侧柔化交给横条切片；需要柔光就离屏生成一次。

**给 R1 的建议**：shell 只渲染当前幕 + 预加载相邻一幕，隐藏的幕暂停 rAF；
否则 5 幕一起跑，单页即使只花 10ms，也会被抢到 20–30fps。

## 4. R1 集成建议

1. **只搬场景，不搬海与 UI。**
   把 `study-scene.js` 的 `makeLayout / makeLayer / render / drawHeat` 搬到 `js/acts/act01.js`；
   `render(s)` 接收 `s.lineY / s.t / s.pointer / s.reduced`，不要自己再算水线。
   背景与水面由 shell 画。
2. **干湿用 shell 的接口。**
   `ctx.clipAbove(lineY)` / `clipBelow(lineY)` 建 path，调用方 `.clip()`；
   湿侧还可以保留 5px 切片，但先做 1–2 个潮位对比再决定步长。
3. **热交给 pointer。**
   R1 的 `s.pointer` 只有归一化坐标与 `down`；建议在 shell 的 pointerdown 里判断
   `hitRock(pointer.x*W, pointer.y*H)`：命中石头 → 加热，不驱动滚动；否则照常拖潮。
   键盘：石头用 `role=button` 覆盖层，`Space/Enter` 按住。移动端命中区不小于 88px 高。
4. **热色可换。**
   本 lab 按任务用珊瑚朱 `#D8503A`；`ART-DIRECTION.md` 的材料表给 01 留了锈红 `#8C4A38`。
   `study-scene.js` 顶部只有一行 `var CORAL = '216,80,58'`，R1 若想让珊瑚朱只归潮位尺，
   改这一行 + 温度读数颜色即可；裂纹/热晕/倒影会一起换。
5. **删掉 lab 专属。**
   `?heat` 强制状态、`?debug` 标题、`preview-mobile.html`、2D 海、DOM 按钮/读数。
   保留 `?p=` 别名方便 review。
6. **移动端先看 360 / 375。**
   390 的标题 91px、题记 8.6px 已经贴边；R1 若换字体或加 safe-area，重新算 `title x = 0.19W`。
7. **R1 验收时至少看三个水线：**
   `p≈0.03` 切标题、`p≈0.55` 切石头、`p≈0.92` 全干沙。湿侧沙粒透明度是第一个要检查的。

## 性能（按“只渲染当前幕”）

- act 每帧只有：shell 的一张背景 + 一次干侧 ink 裁剪贴图 + 55–127 条湿切片 + 按住时的热叠加。
  没有 WebGL、逐像素 shader、`ctx.filter`、`shadowBlur`；没有内嵌图片。
- R0 同一套场景实测：空浏览器 **60fps**，只画场景 **57fps**；R1 去掉了 R0 的海、标题和 UI，
  单帧成本只会更低。R0 的一次性 build 约 45–65ms（两遍场景 + 气孔/沙粒），R1 相同量级。
- 本次 R1 QA 期间，共享浏览器同时开着 8 个 act/QA tab；R1 QA 读数 **5–13fps**，
  同一时刻 R0 lab 也只有 **1–11fps**（前一天空浏览器是 60fps）。这是浏览器/渲染进程被抢，
  不是 act 单页的隔离成本。**最终 60fps 需要 shell 在干净环境 + 隐藏幕暂停 rAF 的条件下测。**
- 低端机降级：湿切片从 6px 调到 8px；DPR 封顶 2；隐藏幕不渲染。高水线 p=.15 有 127 条切片，
  是最大的一帧。

## Shell 接线

1. `mount(root, ctx)`：act 读 `ctx.palette`，注册 Space/Enter，字体 ready 后重建。
2. `resize(w, h, dpr)`：只重建两层离屏，不动背景。
3. `render(s)`：用 `s.lineY` + `ctx.clipAbove/Below` 画；用 `s.pointer.down` + 内部 `hitRock()`
   判断是否按在石头上；按在石头上才升温，其余 pointer 交给 shell。
4. shell 提供 `ctx.onCollect(name)`：约 2.4s 时 act 调一次 `'火'`；收集层自己去重。
5. 章节文案（copy-deck a01）不进 act。高水线 p=.15 时干侧只剩顶部一条，文案应放左上 / 水上，
   或者由 shell 调整该幕的 line 映射；act 已经按 template 的 line 构图。
6. `act.js` 里没有 shell 之外的依赖；`labs/act01/` 交审核后即可原样移到 `js/acts/act01.js`。
